## 2024-08-09 - [ControlKeel Observability Dashboard Optimization]
**Learning:** In the ControlKeel dashboard (`lib/controlkeel/observability.ex`), there are several endpoints computing totals (e.g., `observed_scenarios`, `sessions` in cost groups) over potentially large data sets (like benchmark runs or LLM invocations). The pattern `Enum.map |> Enum.uniq |> length` was causing memory spikes due to building two intermediate lists just to get a distinct count, and `length(Enum.filter)` was allocating a list unnecessarily. The codebase processes these logs frequently, making memory efficiency crucial here to keep the web workers from OOMing on large data loads.
**Action:** Replace distinct counts on streams/lists with `MapSet.new(items, func) |> MapSet.size()`, and filtered counts with `Enum.count(items, condition)` to avoid allocating useless lists in telemetry/dashboard loops.
